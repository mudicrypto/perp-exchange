# Milestone 12 raw measurements

All measurements were taken on one shared container: node v22.22.0, 4 × Xeon @ 2.80 GHz, 16 GiB. They are
local measurements of a simulated prototype, not capacity statements. `9fcee80` is the Milestone 11
baseline (a scratch worktree). "M12" is the Milestone 12 tree.

**Book labels in the logs.** `timing-9fcee80.log` and `public-book-9fcee80.log` come from the timing harness
copied into the `9fcee80` worktree. Their "Book: indexed" line is the CLI default label. The book they
measure is the `9fcee80` sorted array. The `*-reference-book.log` files run the same array, kept as
`src/venue/reference-book.ts`, inside the Milestone 12 engine.

| File | What |
|---|---|
| `golden-hashes-9fcee80.json` | Golden state, output and journal hashes generated by `9fcee80` (`scripts/golden.ts.txt`). `src/venue/book-golden.test.ts` asserts them. |
| `timing-9fcee80.log`, `timing-m12-indexed.log`, `timing-m12-reference-book.log` | `npm run venue:timing -- 5 2000 [indexed\|reference]`: every probe, with 0, 1 000, 10 000 and 50 000 hidden-only levels. `timing-9fcee80-run1.log` is an earlier baseline run that overlapped a `tsc` run. |
| `public-book-*.log` | `npm run venue:timing -- 5 2000 <book> public-book`. These were rerun after the `publicBook` loop fix (see VERIFICATION-REPORT §10). |
| `insert-control.log` | `scripts/control.ts.txt`: insert-front with 50 000 hidden orders on 50 000 levels, on one level, and with none. This separates order count from level count. |
| `timingprobe-corrected-m12.log` | The historical `timingProbe` after the VR-32 fix: 5 rounds × 4 000 samples, engine and gateway paths (`scripts/probe-fixed.ts.txt`). |
| `perf-ab-9fcee80-run{1..4}.log`, `perf-ab-m12-run{1..4}.log`, `perf-ab-summary.md` | `npm run venue:perf -- 1 1`, alternating the two trees, four runs each. Summarised by `scripts/ab-summary.py`. The timing probe sections of these logs still use the old probe (10 000 rested levels). |
| `f1-book-ab.log` | `scripts/f1-book-ab.ts.txt`: the F1 workload in one process, alternating the reference book and the indexed book, 10 runs each. |
| `f6-investigation.log` | `scripts/f6-probe.ts.txt`: the F6 workload in isolation for `9812049` (M10), `9fcee80` (M11) and M12. It runs fresh and after the F2 workload in the same process, 3 rounds. |
| `demo-9fcee80.log`, `demo-m12.log` | `npm run venue:demo`. The two outputs are identical. |
| `check.log`, `e2e.log`, `venue-tests.log` | `npm run check`, `npm run test:e2e`, and the venue suite (verbose). |

**Running a script.** The scripts are stored as `.ts.txt` so the repository typecheck ignores them.

1. Copy one to a `.ts` file outside the repository.
2. Run it with `node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON <script>.ts <tree-root> [args]`.

Here `<tree-root>` is a checkout of the commit being measured.
